Topic 01 · Regression

Linear Regression

Where it all starts: finding the best straight line through a cloud of points. Simple idea — but the way we define "best" quietly decides everything that follows.

1. The big idea: predicting a number

Some questions expect a number as an answer: how much will this house sell for? How many customers will show up? What score will I get if I study 6 hours?

Linear regression answers these with the simplest tool there is: a straight line through the data.

The whole model

$$\hat{y} = w\,x + b$$

The little hat on y means "our prediction" — it keeps our guess separate from the true value.

  • w — the weight (slope). "For every extra unit of x, the answer moves by w." Study one more hour → score rises by 6.5 points → w = 6.5.
  • b — the bias (intercept). The starting value when x = 0. Zero hours studied → still 22 points of baseline → b = 22.
  • Many features? Nothing changes except more sliders: $$\hat{y} = w_1x_1 + w_2x_2 + \dots + b$$ Each weight says how much that one feature matters, holding the others still.

Keep this line in mind

This exact equation reappears in the next topic — logistic regression takes wx + b and wraps it in a squeeze to turn it into a probability. Learn the line well here and half of that page is already done.

2. What "best" means: the misses that matter

Infinitely many lines can be drawn through a cloud of points. To pick one, we first measure how badly each line misses:

Residual — the miss for one point

$$\text{residual} = y - \hat{y} \qquad \text{(actual − predicted)}$$

Graphically it's the vertical gap between a point and the line. The line sits above the point → negative miss; below → positive miss.

We can't just add the raw misses — above and below cancel out, and a line could "cheat" with a score of zero. So each miss is squared first, then we add them all up and pick the line where that total is smallest:

Least squares — the official rule for "best"

$$\text{cost} = \frac{1}{N}\sum_{i=1}^{N} (y_i - \hat{y}_i)^2$$

Squaring makes every miss count as positive — points below the line pay the same as points above. The line with the smallest total is called the least-squares fit.

This total has a name: the cost function

A cost function squeezes the whole model's performance into a single number — lower means better, zero means perfect. Every model you'll ever train has one, and every training algorithm's job is the same: make that number small. In the next topic, logistic regression swaps this formula for log loss, but the job description (one number to minimize) is identical.

Seen 1/(2m) instead of 1/N? Don't worry about it. Some books put a ½ in front of the cost. It's there only so the calculus in their version comes out tidy — the 2 from squaring cancels against it. It never changes which line fits best, so there's nothing to re-learn: same hill, same bottom, same answer. We leave it out to keep the formula simple. (Any positive multiplier works the same way — scaling a number never moves its minimum.)

3. Why squared error? (and its dark side)

Squaring does two friendly things:

  • Everything counts the same direction. A point 3 above the line and a point 3 below both contribute 9 — no canceling.
  • Big misses are taken seriously. One point missing by 9 costs 81; three points missing by 3 cost only 18. The line is pushed hard to fix its worst errors instead of shrugging.

The dark side is the same coin: one weird point gets an outsized vote. A measurement error or a truly strange case (a mansion, a glitch) can drag the line far away from the 99% of normal data. The gentler alternative is to count misses without squaring:

Two ways to count misses

$$\text{MSE} = \frac{1}{N}\sum (y_i - \hat{y}_i)^2 \qquad \text{MAE} = \frac{1}{N}\sum \lvert y_i - \hat{y}_i \rvert$$

MSE = squared error (punishes big misses hard) · MAE = absolute error (every miss votes equally, outlier or not).

Rule of thumb

Default to squared error — it's smooth, fast, and works great when errors are well-behaved. If your data has wild outliers, try absolute error instead (or enjoy the ride — logistic regression's cost function also reacts strongly to bad points, by design).

4. Training: rolling downhill to the best line

There's actually a one-shot formula that jumps straight to the least-squares answer (the "normal equation"). But we'll use gradient descent instead, because it's the general-purpose tool that trains almost every model you'll meet next — logistic regression, neural nets, all of them. The number it minimizes is exactly the cost function from section 2 — that's the hill we're about to roll down.

The recipe is the same rolling-a-ball-downhill story:

  1. Guess a slope and intercept (random is fine).
  2. Check the slope of the squared-error hill under your feet.
  3. Step downhill — move each number by learning rate × slope, in the direction that reduces the error.
  4. Repeat until the slope is ~0. That line is your answer.

The update rule (same one as in logistic regression)

$$w \leftarrow w - \eta \cdot \frac{\partial\,\text{cost}}{\partial w}$$

For squared error the gradient works out to: "(how far off I was) × (that point's feature value), averaged" — exactly the same shape as the gradient you'll meet on the next page.

5. How good is the fit?

After training, you need to speak human about the model's quality. Five metrics, from most literal to most abstract:

MetricPlain EnglishUnits
MAE "On average I'm off by this much." same as y (dollars, points…)
MSE Same as MAE but big misses dominate the average. y's units squared (awkward)
RMSE √MSE — big-miss sensitivity, but units make sense again. same as y
R² "What share of the natural spread did I explain?" unitless 0–1 (can go negative)
Adjusted R² R² that charges rent for every extra feature. unitless

R² in one line

$$R^2 = 1 - \frac{\text{sum of squared misses}}{\text{sum of squared misses of a naive guess}}$$

The naive guess is "always predict the average". So: 1 = perfect · 0 = no better than the average · negative = you'd have been better off not bothering.

The problem with plain R² — and the fix

Plain R² has one sneaky weakness: it never punishes you for adding features. Toss in a completely random junk feature and R² creeps up anyway (more knobs = more chances to get lucky on this particular data). Keep clicking "add feature" and R² will happily climb toward 1 while the model gets no wiser.

Adjusted R² — R² with a feature tax

$$R^2_{adj} = 1 - (1-R^2)\,\frac{n-1}{n-k-1}$$

Here n = how many data points you have, and k = how many features the model uses. The extra fraction is the tax: the more features you add (bigger k), the more R² has to beat just to stay even.

So adjusted R² only rises when a new feature genuinely earns its keep, and sinks when it's just freeload. A tiny worked example — 30 data points, adding one junk feature:

ModelFeatures (k)R²Adjusted R²
Before the junk feature 1 0.800 0.793
After the junk feature 2 0.805 ↑ 0.791 ↓

Rule of thumb

Compare both whenever you're deciding how many features to keep. R² says "sure, take the junk feature"; adjusted R² says "it didn't pay rent — drop it." If the two disagree, your extra features are freeloaders.

Useful pairings: report RMSE to say how big typical mistakes are, and R² (or adjusted R² when features are in question) to say how much of the story the model captures. Always check both — a high R² with a huge RMSE means your data is simply spread far apart.

6. When a line isn't enough

A straight line has one fixed shape. If the real relationship curves — growth that speeds up, a rise then a fall — no amount of tuning w and b will fix it. That's called underfitting: the model is too simple to see the pattern, so it lands somewhere in the middle, mediocre at everything.

More data won't help either — feeding a straight line a million curved points just gives a very confident wrong line. The fix is a richer model. This is the left half of the bias–variance trade-off from Foundations: too little flexibility is just as wrong as too much.

  • Curved data? Feed the model curved features (x², x³ — called polynomial features) or use a model built for curves: decision trees, and later, neural networks.
  • Too wiggly instead? A super-flexible model memorizes noise — that's overfitting, and its cure (keeping the model honest) is exactly the regularization you'll meet in topic 2.

7. The whole thing in ~35 lines of NumPy

No libraries beyond NumPy — same recipe as every later model: guess, measure, step.

import numpy as np

def train(X, y, lr=0.01, steps=4000):
    """Fit weights w and bias b by rolling downhill (gradient descent)."""
    n_samples, n_features = X.shape
    w = np.zeros(n_features)      # start from a flat, boring line
    b = 0.0

    for _ in range(steps):
        pred = X @ w + b                # 1. what the line currently says
        error = pred - y                # 2. how far off each prediction is
        dw = (X.T @ error) / n_samples  # 3. average miss, weighted by each feature
        db = error.mean()
        w -= lr * dw                    # 4. step downhill
        b -= lr * db
    return w, b

def predict(X, w, b):
    return X @ w + b

def r2_score(y_true, y_pred):
    """1.0 = perfect, 0.0 = no better than guessing the average."""
    ss_res = np.sum((y_true - y_pred) ** 2)
    ss_tot = np.sum((y_true - y_true.mean()) ** 2)
    return 1 - ss_res / ss_tot

# ---- try it: hours studied → exam score ----
rng = np.random.default_rng(0)
X = rng.uniform(0, 10, (60, 1))                 # study hours
y = 6.5 * X.ravel() + 22 + rng.normal(0, 4, 60) # score = 6.5·hours + 22

w, b = train(X, y, lr=0.01, steps=4000)
print("weights:", np.round(w, 2), " bias:", round(float(b), 2))
print("R²:", round(float(r2_score(y, predict(X, w, b))), 3))

Typical output:

weights: [6.44]  bias: 22.4
R²: 0.943

Shortcut worth knowing

Least squares also has a direct formula — np.linalg.lstsq(X, y) hands you the answer in one line. Great in practice; but gradient descent is the skill that transfers to every model where no such formula exists.

8. Cheat sheet

The model

$$\hat{y} = w\,x + b$$

Weight × feature + bias.

Residual

$$y - \hat{y}$$

Actual minus predicted — the miss.

Cost (least squares)

$$\frac{1}{N}\sum (y_i-\hat{y}_i)^2$$

Smallest total squared miss wins. Some texts write \(\tfrac{1}{2m}\) — the ½ just tidies their calculus; same best line.

Gradient

$$\frac{\partial L}{\partial w} = \frac{2}{N} X^{T}(\hat{y}-y)$$

(prediction − truth) × feature, averaged.

Update step

$$w \leftarrow w - \eta\,\nabla L$$

Step opposite the slope; η = step size.

Metrics

$$\text{RMSE}=\sqrt{\text{MSE}}, \quad R^2 = 1-\frac{SS_{res}}{SS_{tot}}$$

RMSE = typical miss; R² = story told; adjusted R² charges rent for extra features: \(R^2_{adj} = 1-(1-R^2)\frac{n-1}{n-k-1}\).

Robust variant

$$\text{MAE} = \frac{1}{N}\sum \lvert y_i-\hat{y}_i \rvert$$

Outliers vote equally, not exponentially.

Next topic

$$\hat{p} = \sigma(w\,x + b)$$

This same line, squeezed into a probability.

The five-second recap

Draw a line → count the squared misses → roll downhill until they're smallest → report RMSE and R² → and if the data bends, know that no straight line will ever fit it.

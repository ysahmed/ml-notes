Topic 03 · Classification

K-Nearest Neighbors

The simplest idea in machine learning: don't learn a formula at all — just keep the data around and, when a new question arrives, look at the most similar examples you've seen before.

1. The big idea: just ask the neighbors

Everything so far compressed the data. Linear regression squeezed it into a line; logistic regression into weights and a bend. Both throw the original examples away after training and keep only the formula.

K-Nearest Neighbors (KNN) refuses to do that. It keeps every single row of your data and answers each new question the way a person would: "let me think of the most similar cases I've seen."

The whole algorithm

To predict something new: find the k most similar examples you've stored, and let them vote. The winning class is your answer.

That's it. There is no cost function, no gradient descent, no learning rate. "Training" is just copying the data.

In the vocabulary of Foundations §8, this makes KNN non-parametric: no shape was assumed up front, nothing was fitted — the data itself is the model.

The lazy learner

KNN is famously called a lazy learner: all the work is pushed from training time to prediction time. Training is instant (nothing to compute), but every prediction means measuring the new point against every stored point. The earlier models paid upfront and answered fast; KNN refuses to pay upfront and answers slowly. Remember this in section 7 — the bill always arrives.

And similar is doing all the heavy lifting here — which forces the next question: similar how?

2. What "closest" means: measuring distance

Each example is a list of numbers — its features. To compare two examples, we measure the distance between those lists. The everyday choice is straight-line distance, the same rule as the hypotenuse of a triangle:

Euclidean distance — the straight line between two points

$$d(p, q) = \sqrt{(p_1 - q_1)^2 + (p_2 - q_2)^2 + \cdots + (p_n - q_n)^2}$$

Difference per feature → square each (so negatives can't hide) → add them up → square root. With two features it's literally the Pythagorean theorem. (The alternative that skips the square root — plain sum of differences — is called Manhattan distance; it behaves similarly for KNN.)

One important subtlety: KNN doesn't care about the size of the distances, only their order — which point is first, second, third. Ranking is all the algorithm ever uses. (But keep that ranking honest — section 5 shows what happens when it isn't.)

3. Choosing k: how big is the neighborhood?

k is a dial between two failure modes:

  • k = 1 — paranoid. The prediction copies a single point, so every speck of noise gets its own island of territory. The model hugs the training data perfectly and guesses badly on anything new (overfitting).
  • k = huge — a mob. The vote is taken over so many points that the local pattern drowns out; with two classes, if k reaches the whole dataset, every prediction is just "whichever class is more common overall" (underfitting).

Same two failure modes from Foundations §7 — k is that section's flexibility dial, in vote form: the demo below reports train vs test accuracy as you drag it.

Rules of thumb for k

Use an odd k for two classes (no tied votes). Start somewhere in 3–15, then let the test accuracy from the demo above decide: if test beats train by a mile, k is too small; if both sag, k is too big.

4. Vote or average: one algorithm, two jobs

The same "look at the neighbors" idea works whether you're asked a yes/no question or a number — only the way neighbors are combined changes:

Two ways to combine the k neighbors

$$\text{classification: } \hat{y} = \text{most common class among the } k \qquad \text{regression: } \hat{y} = \frac{1}{k} \sum_{i=1}^{k} y_i$$

Vote if the answer is a label (spam / not spam) · average if the answer is a quantity (price of a house like these five).

So KNN quietly belongs to both topics you've already read: it predicts numbers like linear regression, and classes like logistic regression — it just refuses to fit a formula to do it. (Averaging neighbors is also a nice reminder of why the squared error debate mattered: the mean is least-squares' favorite summarizer.)

5. Why scaling matters: big units bully the vote

Distance formulas are only as sensible as their units. Suppose you store houses with size in sq ft (300–2400) and age in years (1–30). A size difference of 500 sq ft squares to 250,000. An age difference of 10 years squares to 100. The size term is thousands of times louder — so "nearest" quietly becomes "nearest in size", and age stops counting at all, no matter how much you paid for it as a feature.

Scaling — give every feature the same volume

$$x' = \frac{x - \min}{\max - \min}$$

Squash each feature into 0–1 before measuring distances. Now a "big difference" means the same thing for every feature. (Other recipes exist — subtract the average, divide by the spread — the idea is always the same: same units, same voice.)

6. When dimensions multiply: distance loses its meaning

Adding features sounds harmless — more information, better decisions? For KNN it's dangerous. Space gets sparser exponentially fast: with enough features, every point drifts away from every other point, and the "nearest" neighbor ends up almost as far away as the farthest one.

The curse of dimensionality, in plain English

Distance only means something if there's room for near and far to be different. In 2 dimensions, "closest table in the café" is a real, useful idea. In 50 dimensions, the closest table is barely closer than the one across town — so letting it vote is nearly random. When distances stop telling stories, KNN stops working. Prefer fewer, meaningful features over dumping everything you have into the model.

This is also why section 5's scaling isn't optional: one irrelevant noisy feature can flatten all the real distances — one more way for the ranking to lie.

7. Does it actually work? Reading the results

The score that matters for classification is simple: accuracy — out of the predictions, what fraction were right? The catch is which data you score on:

  • Train accuracy is a lie for KNN. With k = 1, every stored point is its own nearest neighbor — it always votes for the point's own label — so train accuracy is guaranteed 100% no matter how useless the model is. Go back to the demo: set k = 1 and read the two numbers.
  • Test accuracy is the confession. Score only on held-out points the model never stored (the hollow dots). The gap between the two numbers is exactly how much the model memorized instead of learned.

One thing accuracy can't show is which kind of mistake you're making. When the classes are unbalanced — or one error hurts more than the other (missing a fraud case vs. annoying a customer) — accuracy is the wrong score to trust. Reach for the precision / recall / F1 toolkit instead; it's worked out with formulas and a worked example in section 7 of Logistic Regression, and it applies here unchanged: KNN's votes are just another classifier's answers.

And don't forget the bill from section 1

Each prediction scans every stored row. Double the data and predictions take twice as long — forever. KNN is wonderful up to tens of thousands of rows; past that, people reach for models that pay once and answer fast (the ones from topics 01 and 02, or the ones coming next).

8. The whole thing in ~30 lines of NumPy

No library needed — KNN is distance, sorting, and a vote:

import numpy as np

def knn_predict(X, y, x_new, k=5):
    """Class of x_new = majority vote of its k nearest stored rows."""
    # 1. distance from x_new to every stored point (Pythagoras, all at once)
    d = np.sqrt(((X - x_new) ** 2).sum(axis=1))
    # 2. the k smallest distances -> which rows are the neighbors
    idx = np.argsort(d)[:k]
    # 3. let them vote
    labels, counts = np.unique(y[idx], return_counts=True)
    return labels[np.argmax(counts)]

def knn_average(X, y, x_new, k=5):
    """Regression version: average instead of vote."""
    d = np.sqrt(((X - x_new) ** 2).sum(axis=1))
    return y[np.argsort(d)[:k]].mean()

# usage: predict the class of one new point
# knn_predict(X_train, y_train, x_new=[1200., 14.], k=5)

Two lines of math, one line of voting — which is why this algorithm is usually the first thing people implement from scratch to check they understand the whole train-predict loop.

9. Cheat sheet

Distance

$$\sqrt{(p_1-q_1)^2 + \cdots + (p_n-q_n)^2}$$

Straight-line distance; KNN only uses the ranking.

Classification rule

$$\hat{y} = \text{majority of } k \text{ neighbors}$$

Odd k avoids tied votes.

Regression rule

$$\hat{y} = \tfrac{1}{k}\sum_{i=1}^{k} y_i$$

Same neighbors, averaged instead of voted.

Choosing k

Small k = jagged (overfit) · large k = bland (underfit).

Start 3–15; let test accuracy decide.

Scaling

$$x' = \tfrac{x - \min}{\max - \min}$$

Scale first — or big-unit features bully the vote.

The lazy learner

Training = copy the data (instant).

Prediction = scan all of it (the bill arrives later).

The one-sentence version

KNN remembers everything, measures distance, and lets the k closest memories vote — the whole art is picking k, trusting your distances, and keeping the dimensions few.

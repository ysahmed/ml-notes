Topic 05 · Trees

Decision Trees

The flowchart you'd draw yourself — except learned from data. A stack of yes/no questions carves the world into boxes until each box can answer, and every decision along the way is a sentence a human can read.

1. The big idea: twenty questions

Every model so far handed you something you can't picture: a line's weights, a probability formula, a neighbor's vote. A decision tree hands you something you already know how to read — a flowchart, the same structure you use yourself: "if the email says 'wire' and asks for money today → spam."

The whole algorithm

1. Start with all the data in one node (the root). 2. Ask the yes/no question that splits the data into two groups that are each as pure as possible. 3. Repeat on each group — split, split, split. 4. Stop when told to. The answer in each final node (leaf) = the majority class or the average of whatever landed there.

"Training" is choosing the questions — no gradient descent, no distance metric. Just repeated brute force: try every question, keep the one that separates best.

To predict, you drop a new row down the tree — answer left or right at each junction — until it lands in a leaf. That's it. The learning all happened while choosing the questions; running it is free.

2. What makes a split "good"? Purity

Step 2 needs a ruler: how mixed is a node? The standard ruler is the Gini index — zero for a perfectly pure node, higher for a mess:

Gini index — how muddied is this node?

$$\text{Gini} = 1 - \sum_{m} \hat{p}_m^2$$

$\hat{p}_m$ = the fraction of the node that belongs to class m. All one class → 1 − 1² = 0 (pure). Dead-even two classes → 1 − 0.5² − 0.5² = 0.5 (maximum muddle).

A quick taste: a node with 7 blue, 3 red gives 1 − (0.7² + 0.3²) = 0.42. Split it into 7-blue and 3-red, and both children score 0 — the split destroyed 0.42 of muddle. The algorithm's entire ambition: find the question that drops the average Gini of the children as far as possible (weighted by how many points land in each side).

There's a rival ruler — entropy, from information theory:

Entropy — same job, different curve

$$\text{entropy} = -\sum_{m} \hat{p}_m \log_2 \hat{p}_m$$

Zero for pure nodes, 1.0 for a balanced two-class node. Different numbers, same rankings: trees built with Gini and trees built with entropy almost always end up identical.

3. Growing the tree: split, split, split

After the first question, each side gets its own best question, ignoring the other side. Recursion does the rest — and because every question is "feature < threshold?", the tree's map of the world is always drawn in axis-aligned rectangles: cut horizontally, cut vertically, never diagonally.

Watch the leaf boxes counter while you drag: it's the model's size. Two boxes = one question and a shrug; two dozen boxes = a hand-carved map of every noise pocket in the training set.

5. Overfitting & pruning: the flexibility dial

Left alone, a tree grows until every training point sits in its own pure leaf — training error zero, test error embarrassed. Stopping it is regularisation, and you get two flavors:

Flavor 1 — stop early (limit the tree while it grows)

  1. max depth — how many questions deep a path may go.
  2. min samples per leaf — no box smaller than n points (a leaf needs a crowd to vote, not one dictator).
  3. min samples to split — don't bother splitting a node with fewer than n points.

Flavor 2 — grow big, then prune (cost-complexity, ISLR's "weakest link")

  1. Grow a giant tree that fits the training data perfectly.
  2. Score every subtree: $$\text{cost} = \text{training error} + \alpha \cdot (\#\text{leaves})$$
  3. α is a dial: α = 0 keeps the giant; huge α collapses to a stump. Pick the subtree with the best cost — usually by cross-validation.

It's the same dial again

Depth ↔ k in KNN ↔ polynomial degree: tree depth is the flexibility dial of the tree world (Foundations §7). Too shallow: high bias, boxes too big. Too deep: high variance, boxes memorize noise. Drag the two demos above until the train/test gap tells you where the bottom of the U is — that's your depth.

6. Trees vs linear models

Two opposite temperaments, and knowing which world you live in picks the winner (ISLR calls this out as its own subsection):

If the real pattern is…Reach for
Smooth and roughly linear — a straight-ish effect, one slope for the whole range Linear / logistic regression: fewer knobs, honest extrapolation, coefficients you can quote
Curvy, tiered, or boundary-shaped — thresholds, plateaus, "only matters above X" A tree: no feature engineering, no transforms — it carves the shape itself

The tree's superpower is readable complexity. A deep network is complex and opaque; a logistic model is simple and readable. A tree is the odd one out — complex and readable: every prediction is a sentence ("if price < 50k, and size ≥ 900, then…"), and you can rank features by how much impurity each question destroyed along the way.

7. Strengths & weaknesses

  • ✅ No scaling, mixed features welcome. Prices, sizes, and yes/no columns can share a tree without normalization or one-hot gymnastics — each question only ever touches one feature.
  • ✅ Interpretable to a fault. Export the rules, show them to a stakeholder, done. No other model here lets every decision be audited.
  • ❌ Staircases instead of diagonals. A clean diagonal boundary takes dozens of axis-aligned steps — many boxes, deep tree, fragile fit.
  • ❌ Unstable. Nudge the training data and the whole tree can reorganize: early splits change, later branches swap (Géron's "instability"). Two trees trained on 95% of the same data can look like strangers.
  • ❌ Can't extrapolate. Predict beyond the training range and a regression tree just keeps its edge leaf's mean flat forever — no idea that trends continue. (Géron's comet: it would never see a brighter one coming.)
  • ❌ A single tree usually loses on accuracy. On its own it's a weak learner — which is exactly why the next section exists.

8. One tree → many trees

A single tree's instability turns out to be a feature when you plant a whole forest. Give each tree a slightly different, shuffled copy of the data (bootstrap samples), let them all disagree, then average their votes — the wobbles cancel and the shared signal survives. That's bagging, and if you also randomize which features each tree may consider, you get the random forest. Boosting goes the other way: many small stumps built in sequence, each one focused on fixing the previous ones' mistakes.

The trade you're making

An ensemble gives up the auditability of one flowchart for real accuracy — you can no longer print the model on a page. This is flexibility vs interpretability (Foundations §8) in its purest form. The details — bagging, random forests, boosting — are all here in ISLR §8.2 / Géron ch.7; they're a natural future topic.

9. The whole thing in ~30 lines of NumPy

Gini, brute-force splitting, recursion — there's genuinely nothing else in the box:

import numpy as np

def gini(y):
    _, counts = np.unique(y, return_counts=True)
    p = counts / counts.sum()
    return 1 - (p ** 2).sum()

def best_split(X, y):
    parent, gain, best = gini(y), 0, None
    for f in range(X.shape[1]):                 # every feature,
        vals = np.unique(X[:, f])
        for a, b in zip(vals[:-1], vals[1:]):   # every threshold
            thr = (a + b) / 2
            L, R = X[:, f] < thr, X[:, f] >= thr
            if L.sum() < 2 or R.sum() < 2:
                continue
            w = (L.sum()*gini(y[L]) + R.sum()*gini(y[R])) / len(y)
            if parent - w > gain:               # keep the purest split
                gain, best = parent - w, (f, thr)
    return best

def grow(X, y, depth=0, max_depth=5):
    if depth == max_depth or len(np.unique(y)) == 1 or len(y) < 4:
        return lambda Xt: np.full(len(Xt), np.bincount(y).argmax())   # leaf: majority
    f, thr = best_split(X, y)
    L, R = X[:, f] < thr, X[:, f] >= thr
    left, right = grow(X[L], y[L], depth+1, max_depth), grow(X[R], y[R], depth+1, max_depth)
    return lambda Xt: np.where(Xt[:, f] < thr, left(Xt), right(Xt))   # route the question

# tree = grow(X_train, y_train, max_depth=4)
# preds = tree(X_test)

The functions return functions — training builds a nested yes/no machine you then call with new rows. Swap the leaf line for y.mean() and the split line for squared error, and you have a regression tree instead.

10. Cheat sheet

The algorithm

Split → recurse → stop. Training = choosing questions by brute force.

Predict = drop the row down the tree to a leaf.

Gini (or entropy)

$$\text{Gini} = 1 - \sum_m \hat{p}_m^2$$

0 = pure node. Best split = biggest weighted Gini drop. Entropy agrees.

Two flavors

Classification leaf = majority vote; regression leaf = mean of the leaf.

Splits: Gini vs RSS. Same greedy habit either way.

Always axis-aligned

Questions are "feature < threshold?" — the map is rectangles and steps.

Diagonals cost many boxes; extrapolation isn't possible.

Regularize

Stop early (depth, min-samples) or prune: cost = error + α · leaves.

Depth is the flexibility dial — pick it from the train/test gap.

When to pick one

Nonlinear/threshold patterns, mixed features, stakeholders who ask "why?".

Reach for linear models when the pattern is smooth and roughly straight.

Honest weaknesses

Unstable (data nudges reshuffle the tree) · no extrapolation · rarely wins alone.

Instability is exactly what ensembles are for.

Forests ahead

Bag → average = bagging; random features = random forest; sequential fixes = boosting.

The one-sentence version

Ask the question that splits the crowd into the two purest groups, repeat until you're told to stop, and let each box vote or average — a flowchart learned by brute force, one axis-aligned cut at a time.

Topic 02 · Classification

Logistic Regression

You already know how to draw a best-fit line. Here we bend that line into a probability, and find out why "how wrong am I?" matters more than "how far off am I?".

1. The big idea: a line that answers yes/no

Linear regression predicts a number. Feed it a house's size, it says "$312,000". Any answer is allowed — small, large, even negative. That freedom is a feature when you're predicting prices.

Logistic regression answers a different kind of question: yes or no — is this email spam? Will this user click? Does this tumor look malignant? The honest answer isn't just "yes", it's "how sure are you?" — a probability from 0% to 100%.

So the natural move is: take the same data you'd feed a linear regression (numbers in, label 0 or 1 out), fit a line… and then worry, because two things go wrong:

Problem 1: the line can say impossible things

A line never stops — it happily predicts -0.3 or 1.7. But a probability of −30% or 170% doesn't mean anything. The output needs to be trapped between 0 and 1.

Problem 2: one weird point ruins everything

A single extreme point drags the whole line toward it. Where the line crosses the 0.5 mark (our "yes/no" dividing line) can jump a long way — so one outlier silently changes thousands of predictions.

The fix in one sentence

Keep the straight line, but wrap it in a squeezing function that crushes any input into the 0–1 range. That wrapper is called the sigmoid (or logistic) function — and that's the whole model.

2. The squeeze: meet the sigmoid

The sigmoid takes any number on the number line and squashes it into (0, 1):

The sigmoid function

$$\sigma(z) = \frac{1}{1 + e^{-z}}$$

Read it as: "give me any number z, I'll hand back a smooth probability."

What it does, in plain terms:

  • Input 0 → output 0.5. Perfectly undecided.
  • Big positive input → output close to 1. At z = 6 you already get 0.9975 — "basically yes".
  • Big negative input → output close to 0. At z = −6 you get 0.0025 — "basically no".
  • It's symmetric: σ(−z) = 1 − σ(z). Being 90% sure "yes" is the same shape as being 90% sure "no".
  • It never quite reaches 0 or 1 — the curve approaches the edges forever. (Handy later: the model never claims 100% certainty, so it can always learn more.)

Slope you should remember

The slope of the sigmoid has a neat formula: the slope at any point is just σ(z) × (1 − σ(z)) — that is, answer × (1 − answer). When you're near 0 or 1 the answer is almost fixed, so the product is near zero: the curve is flat, and flat means "nothing to learn from here".

3. The model: weights, bias, and hidden meaning

Logistic regression looks like this:

The whole model

$$z = w_1x_1 + w_2x_2 + \dots + b \qquad \text{then} \qquad \hat{p} = \sigma(z)$$

Step 1: score the features (a line). Step 2: squash the score into a probability.

The pieces, in everyday language:

  • Weights w — how much each feature matters. A big positive weight means "this feature pushes the answer toward yes"; a negative weight means "toward no".
  • Bias b — the starting opinion before seeing any feature. If spam is rare, the bias starts low.
  • z — the raw score from the line, before squashing.
  • ŷ ("y-hat") — our predicted probability for class 1. Above 0.5 → predict "yes", otherwise "no".

What the line is really predicting: the log-odds

Un-doing the squeeze (algebra you can skip if you like) shows what z actually means:

Where the formula comes from (3 lines)

  1. Start with the goal: p is the probability of "yes".
  2. Take the odds — "yeses per no" — and then its logarithm: $$\log\frac{p}{1-p} = z$$ Example: probability 0.75 → odds 3 (three yeses per no) → log-odds ≈ 1.10.
  3. Solve that equation for p and you get exactly p = σ(z) back again.

So the straight line predicts log-odds, and the sigmoid converts log-odds back into a probability. The name "logistic" comes from this log-odds (logit) link.

The decision boundary

Our yes/no rule is "probability above 0.5 → yes". Probability is 0.5 exactly when z = 0. So predictions flip when the line crosses zero — and in multiple dimensions, z = 0 is just a line (or, with many features, a flat sheet) drawn through the data. That's the decision boundary.

4. The cost: putting a price on being wrong

A model is only as good as how it grades itself. When the true answer is "yes" (1) and we predict a probability p, we charge ourselves:

Cost of one prediction (cross-entropy / log loss)

$$\text{cost} = -\big[\, y \log(\hat{p}) + (1-y) \log(1-\hat{p}) \,\big]$$

If the label y is 1 the second part vanishes and the cost is −log(p). If y is 0, the first part vanishes and it's −log(1−p). The total cost is just all the individual charges added up.

Why this particular shape? Two plain-English reasons:

  • It's the honest "how likely was this data?" Every point votes for its true label with probability p; all votes multiply. Multiplying many small probabilities gives an astronomically tiny number, so we take the log to turn the product into a tidy sum — and flip the sign so that bigger cost = worse model.
  • Confident mistakes are punished hard. Predicting 0.9 when the answer is 1 costs only 0.1. Predicting 0.01 costs 4.6 — 46 times worse, even though both were "off by 0.9". The message: never be cocky and wrong.

Why not just reuse the linear-regression loss (MSE)?

Mean squared error — "average of (prediction − truth)²" — is the natural first guess, and it fails for two visible reasons:

  1. The slope dries up. Plug the sigmoid into MSE and, when the model is confidently wrong, both curves are flat, so the gradient is nearly zero. Learning almost stops exactly when you need it most.
  2. The landscape gets bumps. A bumpy (non-convex) loss has local dips that aren't the bottom — gradient descent can get stuck. Log loss is a smooth bowl: one bottom, always found.

Why the bowl shape matters

A convex loss is like a bowl: tilt it anywhere and a ball rolls to the same bottom. Log loss has this property, which means gradient descent always finds the best weights — no unlucky starting point can trap it.

5. Training: rolling downhill

We now have a model (section 3) and a grade sheet (section 4). Training means: adjust the weights until the cost is as small as possible. The tool is gradient descent, which works exactly like rolling a ball downhill:

  1. Guess starting weights (random is fine).
  2. Check the slope of the cost under your feet — pointing downhill?
  3. Step in the opposite direction of the slope, by learning rate × slope.
  4. Repeat until the slope is ~0 (you've reached the bottom).

The update rule

$$w \leftarrow w - \eta \cdot \frac{\partial \,\text{cost}}{\partial w}$$

η (eta) is the learning rate — how big each step is.

The gradient has a beautiful shape

Work through the calculus (chain rule: cost → probability → score) and almost everything cancels, leaving:

The gradient, in one line

$$\frac{\partial \,\text{cost}}{\partial w_j} = \frac{1}{N}\sum_{i=1}^{N} (\hat{p}_i - y_i)\, x_{ij}$$

Sentence translation: "for every example, take how far off I was (prediction − truth), multiply it by that example's feature value, then average." That's it.

  • Predicted too high → difference is positive → weight is pushed down.
  • Predicted too low → difference is negative → −negative = weight pushed up.
  • Predicted just right → difference ≈ 0 → no movement. We've arrived.

Choosing the learning rate η is a balancing act:

  • Too small — correct direction, but you'll be here all day.
  • Too big — each step overshoots the valley and you bounce (or fly off entirely).
  • Just right — quick, steady descent to the bottom.

6. Keeping it simple: regularization

With enough freedom, a model can get a perfect score on its training data by memorizing every quirk and stray point — including pure noise. Then it fails on new data. That's overfitting: straight-A student who's never solved a problem they haven't seen before.

Regularization is a penalty added to the cost that says: "getting the right answer matters — but so does keeping your weights small."

L2 regularization (the common one, a.k.a. "Ridge")

$$\text{total cost} = \text{log loss} + \frac{\lambda}{2}\sum_j w_j^2$$

λ (lambda) is the dial: 0 = no restraint, large = "keep those weights tiny!". Huge weights mean the model is reacting violently to small features — usually a sign it's fitting noise.

L1 regularization (a.k.a. "Lasso")

$$\text{total cost} = \text{log loss} + \lambda \sum_j |w_j|$$

Same idea, different shape. The absolute-value penalty is so eager to shrink weights that it pushes useless features all the way to exactly 0 — the model automatically deletes them. Nice when you suspect some features are just noise.

7. Did it actually work? Reading the results

The simplest scorecard of all — wrong ÷ total — is the classification error rate from Foundations §9, along with the floor (Bayes error) that no model may cross. Its twin, accuracy, is misleading as soon as classes are unbalanced: if only 5% of emails are spam, a model that always says "not spam" scores 95% while being useless. So start with the confusion matrix — who got confused with whom:

Predicted: spamPredicted: not spam
Actually spamTP = 48 ✅ caughtFN = 2 missed
Actually not spamFP = 6 false alarmTN = 44 ✅ correctly ignored

From those four numbers, five useful questions:

  • Accuracy — "over all predictions, what fraction is right?" In this example: (48 + 44) / 100 = 92%. Balanced classes? Accuracy is the perfectly fine go-to number — it's exactly the number whose danger the opening paragraph warned about.

$$\text{accuracy} = \frac{TP + TN}{N}$$

  • Precision — "when it raises an alarm, how often is it right?" Here: 48 / 54 ≈ 89%.

$$\text{precision} = \frac{TP}{TP + FP}$$

  • Recall — "of all the real cases, how many did we catch?" Here: 48 / 50 = 96%.

$$\text{recall} = \frac{TP}{TP + FN}$$

  • F1 score — one number that respects both, folded together with the harmonic mean (the kind that punishes lopsidedness). When precision and recall are both high, F1 sits near them anyway (here ≈ 92%). The difference shows when they split: 99% precision but 50% recall averages out to a comfortable 74% — F1 grades it 67%, because a model that only flags the obvious cases hasn't really caught anything.

$$F_1 = 2 \cdot \frac{\text{precision} \cdot \text{recall}}{\text{precision} + \text{recall}}$$

  • ROC curve / AUC — slide the 0.5 cutoff down toward 0 and you catch more (recall up) but cry wolf more (precision down). The ROC curve plots that trade-off for every possible cutoff; the AUC compresses it to one number: 1.0 = perfect, 0.5 = coin flip.

So when do you reach for which? Every row is an answer to the same question: who pays for each mistake?

SituationReportWhy, in one line
Balanced classes, every mistake equally costly Accuracy The everyday default — nothing to hide.
False alarms are the disaster (deleting real email, blocking legit transactions) Precision "When it raises an alarm, how often is it right?"
Missing a real case is the disaster (fraud, cancer, defects) Recall "Of all the real cases, how many did we catch?"
You need one number to compare models and both error types matter F1 Collapses if either side collapses — can't hide a lopsided model.
Heavy class imbalance (5% fraud) — accuracy looks great but lies AUC Grades every threshold at once, so one lucky 0.5 cutoff can't fake it.
You must tune where the cutoff sits (catch more vs. cry wolf) ROC curve Shows the full trade-off so you can pick the balance deliberately.

Rule of thumb

The table is a menu, not a law. Ask yourself "which mistake hurts more?", pick the number whose failure mode you can live with — and always ship the confusion matrix next to your score, so nobody has to guess what it's hiding.

8. More than two answers: softmax regression

Yes / no is fine, but what about "cat, dog, or bird?" Softmax regression (a.k.a. multinomial logistic regression) generalizes everything above:

Softmax: one score per class, normalized

$$\hat{p}_k = \frac{e^{z_k}}{\sum_{c} e^{z_c}}$$

Each class gets its own line z_k = w_k · x + b_k. We exponentiate (make positive, amplify leaders), then divide by the total so all probabilities add up to exactly 1.

The same story, restated: scores from lines → a squashing step → a probability distribution → log-loss cost → gradient descent. With two classes, softmax gives the same answers as the sigmoid model you just learned. It's the same idea wearing a bigger hat.

9. The whole thing in ~40 lines of NumPy

No libraries beyond NumPy. The comments are the same intuition as above, in order.

import numpy as np

def sigmoid(z):
    """Squeeze any number into the (0, 1) range."""
    return 1 / (1 + np.exp(-z))

def train(X, y, lr=0.1, steps=1000, lam=0.0):
    """Fit weights w and bias b with gradient descent + optional L2 (lam)."""
    n_samples, n_features = X.shape
    w = np.zeros(n_features)      # start with a blank slate
    b = 0.0

    for _ in range(steps):
        # 1. Score each example, then squeeze scores into probabilities
        z = X @ w + b
        p = sigmoid(z)

        # 2. Gradients: (how wrong) x (feature value), averaged over the data
        error = p - y                        # prediction - truth
        dw = (X.T @ error) / n_samples + lam * w   # the + lam*w is the L2 pull
        db = error.mean()

        # 3. Step downhill
        w -= lr * dw
        b -= lr * db

    return w, b

def predict_proba(X, w, b):
    """Turn features into probabilities of class 1."""
    return sigmoid(X @ w + b)

def predict(X, w, b, threshold=0.5):
    """Same, but forced to a yes/no answer."""
    return (predict_proba(X, w, b) >= threshold).astype(int)

# ---- try it on a small two-blob dataset ----
rng = np.random.default_rng(0)
X = np.vstack([rng.normal([-1.5, -1.5], 1.0, (50, 2)),
               rng.normal([ 1.5,  1.5], 1.0, (50, 2))])
y = np.array([0] * 50 + [1] * 50)

w, b = train(X, y, lr=0.5, steps=2000, lam=0.01)
acc = (predict(X, w, b) == y).mean()

print("weights:", np.round(w, 3), " bias:", round(float(b), 3))
print("accuracy:", f"{acc:.0%}")

Typical output:

weights: [1.076 1.093]  bias: -0.03
accuracy: 98%

That's the entire algorithm. Everything else in this lesson — the squeeze, the cost, the gradient, the penalty — is visible right here in the code.

10. Cheat sheet

The model

$$\hat{p} = \sigma(w \cdot x + b)$$

Line → squeeze → probability.

Sigmoid

$$\sigma(z) = \frac{1}{1+e^{-z}}, \quad \sigma'(z)=\sigma(z)(1-\sigma(z))$$

S-shaped, 0→0.5, flat at the ends.

Decision boundary

$$w \cdot x + b = 0$$

Where the probability crosses 0.5.

Cost (log loss)

$$-\big[y\log \hat{p} + (1-y)\log(1-\hat{p})\big]$$

Smooth bowl; confident mistakes cost dearly.

Gradient

$$\frac{\partial L}{\partial w} = \frac{1}{N} X^{T}(\hat{p}-y)$$

(prediction − truth) × feature, averaged.

Update step

$$w \leftarrow w - \eta \,\nabla L$$

Step opposite the slope; η = step size.

Regularization

$$L + \tfrac{\lambda}{2}\|w\|^2 \;\;(\text{L2}) \qquad L + \lambda\|w\|_1 \;\;(\text{L1})$$

Shrink weights; L1 can zero them out.

Many classes

$$\hat{p}_k = \frac{e^{z_k}}{\sum_c e^{z_c}}$$

Softmax — same story, more heads.

Scores

$$\text{acc}=\tfrac{TP+TN}{N},\;\; \text{prec}=\tfrac{TP}{TP+FP},\;\; \text{rec}=\tfrac{TP}{TP+FN},\;\; F_1=\tfrac{2PR}{P+R}$$

One number never tells the whole story — pick the one where your mistakes hurt.

The five-second recap

A line scores the features → the sigmoid turns the score into a probability → log loss punishes overconfident mistakes → gradient descent nudges the weights downhill → regularization keeps them from memorizing noise.
